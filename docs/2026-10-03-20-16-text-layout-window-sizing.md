# Text layout and window sizing

## Summary
Center annotation text, create wider text boxes, preserve off-image editing positions, and size new windows relative to their screen.

## Product behavior target
Text is centered horizontally and vertically during editing and in output. New boxes extend from the click toward the expanded canvas right edge with a 20-pixel margin and a 260-pixel minimum where possible. Initial height is at least 76 pixels or one text line plus padding. Typing grows height without changing width or origin. Opening an editor alone never changes geometry or history. New windows use 70% of usable screen width and height.

## Architecture changes
Share TextKit measurement, paragraph attributes, and padding between the core renderer and editor. Remove original-image bounds constraints from editor lifecycle and typing. Keep initial placement bounded to the current expanded canvas. Calculate window frames from screen visible bounds and preserve constrained cascading.

## UX acceptance criteria
- Short and multiline text remains centered through editing, commit, zoom, Copy, and export.
- Text outside any original image edge edits in place, including negative coordinates and oversized boxes.
- Opening and closing an editor without changes preserves bounds and revision.
- Typing grows height only as needed; deleting does not shrink it. Existing overflow scrolls on entry.
- New boxes leave a 20-pixel margin, reduced to a quarter of the smaller canvas dimension on tiny canvases.
- First windows are centered; subsequent windows cascade on the active window's screen. Minimum frame is 760 by 520 where the display permits.

## Automated test plan
Add core checks for placement and shared text metrics/rendering. Extend standalone AppKit checks for off-image editing, unchanged history, growth and undo/redo, editor/rendering consistency, and screen sizing. Update obsolete checks that require typing to stay inside the original image. Run the required Xcode test command and scripts/check_windows.sh.

## Manual verification plan
Launch the built Capture.app. Inspect centered short and multiline text while editing and after commit, including an off-image annotation. Capture and inspect screenshots under artifacts/verification. Verify the default window proportions and exported image layout.

## Assumptions and non-goals
Preserve lower-left image-space origin during growth. Keep existing background opacity and other tools unchanged. No persistence or release changes. Preserve the user's existing release-notes edit. Differences from Skitch are intentional: sizing follows the chosen click-to-right-edge and automatic-height-growth behavior.
